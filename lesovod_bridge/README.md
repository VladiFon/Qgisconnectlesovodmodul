# Лесовод-мост

Отдельный QGIS-плагин (PyQGIS). Кнопка «Опубликовать в Лесовод» читает
контуры лесосек из таблицы `area` в базе ГИСлесхоз (RUP «Белгослес»,
PostgreSQL/PostGIS) **только на чтение** и отправляет их на сервер
«Лесовод» одной пачкой `layer_name = "qgis_lesoseki"`, полностью
заменяя предыдущее содержимое этой пачки.

Плагин ГИСлесхоз не редактируется и не трогается — работает рядом,
своей отдельной кнопкой в панели инструментов QGIS.

## Установка

Скопируйте папку `lesovod_bridge` в профиль QGIS
(`QGIS3/profiles/default/python/plugins/`) и включите плагин в
Модули -> Управление модулями.

Зависимости (обычно уже есть в окружении QGIS): `psycopg2`.

## Настройка

Меню «Лесовод-мост -> Настройки Лесовод-моста…»:

1. Пять полей подключения к базе ГИСлесхоз (host, порт, имя базы,
   пользователь, пароль) — те же самые значения, что в самом ГИСлесхоз:
   шестерёнка (настройки) -> вкладка «База данных». Ничего не зашито в
   код, вводится руками.
2. Адрес сервера «Лесовод» (по умолчанию `https://lesovodapipom.store`).
3. Токен (`Authorization: Bearer <токен>`, значение
   `LESOVOD_MAP_IMPORT_SERVICE_TOKEN`) — вводится руками, не хранится в
   коде.
4. Номер лесничества — необязательный фильтр/метка (`lesnichestvo_num`),
   можно оставить пустым.

## Реальный контракт сервера (подтверждён по openapi.json)

Путь и формат взяты из `openapi.json`, который прислал пользователь
(эндпоинты сервера «Лесовод», тег `map`), а не придуманы:

- `POST /api/map/import-layer` — `multipart/form-data`, файл в поле
  `file` (GeoJSON/Shapefile.zip/экспорт «Лесной страж»), query-параметры
  `layer_name` (используется `"qgis_lesoseki"`) и опционально
  `lesnichestvo_num`. Один вызов = один новый `batch_id`; сервер сам
  не заменяет предыдущую загрузку с тем же `layer_name`.
- `GET /api/map/import-layers/batches` — список загруженных пачек.
- `DELETE /api/map/import-layers/{batch_id}` — удалить пачку целиком.

Поскольку сервер не делает автозамену по имени слоя, требование 3
промпта (полная замена одной пачки при каждой публикации) реализовано
на стороне плагина (`publisher.publish`): перед загрузкой нового файла
плагин находит все прежние пачки с `layer_name == "qgis_lesoseki"` и
удаляет их, и только потом грузит новый GeoJSON.

## Остаточная неопределённость

`openapi.json` не типизирует тела ответов этих ручек (FastAPI отдаёт
произвольный dict/list без pydantic-модели), поэтому:

- Точные имена полей в ответе `GET .../batches` (как называется
  идентификатор пачки и имя слоя в каждой записи) распознаются защитно
  (`_extract_batch_id`/`_extract_layer_name` в `publisher.py`, пробуют
  варианты `batch_id`/`id` и `layer_name`/`name`). Если формат окажется
  другим — публикация прерывается с понятной ошибкой вместо удаления
  наугад.
- Ожидаемая система координат геометрии (WGS84/EPSG:4326 или другая) —
  в openapi.json не указана. Плагин передаёт геометрию из базы
  ГИСлесхоз как есть, без перепроецирования.

Если что-то из этого разойдётся с реальным поведением сервера —
дайте знать, поправим по факту, а не по предположению.

## Формат данных

`geom` в таблице `area` — двоичная геометрия (EWKB), а не текст: запрос
берёт её как `ST_AsGeoJSON("geom") AS geom`, поэтому в код плагина
приходит уже готовый GeoJSON-геометрией текстом. Строки, где
`ST_AsGeoJSON` вернул пустое значение (`NULL`), пропускаются, а не
роняют всю публикацию — о них выводится предупреждение.
